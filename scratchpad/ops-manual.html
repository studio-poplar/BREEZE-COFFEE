Breeze Coffee 運用マニュアル

レジ・メイク・客用ディスプレイの3台構成で動く注文システムの、日常運用と緊急時対応のガイドです。 迷ったときはまずこのページで探してください。

Studio Poplar 制作 最終更新 2026年9月4日
Daily Operation

開店前に開く3つの画面

それぞれ別の端末で開いたままにしておきます。レジとメイクはスタッフアカウントでログインが必要、 客用ディスプレイはログイン不要です。

会レジ(会計担当)
  1. QRコードを読み取る、または注文番号を入力
  2. 内容を確認 — 必要ならその場で商品を追加・削除
  3. 支払い方法を選択(現金の場合はお預かり金額を入力)
  4. 会計確定 → 自動でレジ画面に戻る
breeze-coffee.vercel.app/register
提メイク(バリスタ)
  1. 「提供待ち」一覧が自動更新される
  2. 作る注文をタップして開く
  3. 商品ごとに「提供済みにする」
  4. すべて済んだら「提供完了にする」
breeze-coffee.vercel.app/register/maker
客客用ディスプレイ
  1. URLを開いてブックマークするだけ
  2. レジが注文を開くと自動で内容・金額を表示
  3. 会計後は支払い方法・おつりを2分間表示
  4. ログイン操作は一切不要
.../display/e45ce541-...
💡

3台とも画面が自動でスリープ(消灯)すると更新が止まります。営業中は端末の画面ロックをオフにしておいてください。

Admin Tasks

管理者(admin)ができること

/admin から管理者アカウントでログインして操作します。

スタッフの追加・編集・パスワードリセット
/admin/staff
  1. 「スタッフ管理」を開く
  2. 新規追加はユーザー名・初期パスワード・表示名・ロール・担当店舗を入力して作成
  3. 退職者が出たら削除ではなく「編集」→「有効なアカウント」のチェックを外す(履歴データを壊さないための仕様)
  4. パスワードを忘れた場合も「編集」→「パスワードをリセット」で本人確認なしに変更可能
⚠️

自分自身のアカウントは無効化できません(ロックアウト防止のため)。

メニューの追加・編集・原価設定
/admin/[店舗ID]/menu
  1. 店舗一覧から対象店舗の「メニュー」を開く
  2. 商品ごとに「原価」を入力すると、粗利率が売上管理に自動反映される
  3. 画像は自動でリサイズされるので、スマホ撮影の写真をそのままアップロードしてOK
  4. 注文履歴がある商品は削除できない仕様(誤って過去データを壊さないため)。使わなくなったら「非公開」に
売上・粗利の確認
/admin/[店舗ID]/sales
  1. 今日・昨日・今週・今月・過去7日・期間指定から選択
  2. 売上合計、原価合計、粗利率、日別推移、商品別収益性、支払い方法別の内訳が見られる
  3. 粗利率30%未満の商品があると自動で警告表示される
領収書・レシートの発行元情報の設定
/admin/stores
  1. 店舗一覧の「領収書設定」から住所・電話番号・インボイス登録番号を入力
  2. 未入力の項目はレシート・領収書に表示されない(必須ではない)
  3. 領収書・レシート自体はレジの会計後の注文画面から都度発行する(「レシートを発行」「領収書を発行」)
Troubleshooting

よくある症状と対処

症状原因対処
ログインできない パスワード間違い、または5回連続失敗でロック 15分待つか、管理者に「パスワードをリセット」してもらう
客用ディスプレイが更新されない 端末の画面がスリープしている 画面ロックの設定をオフにする、または一度タップして起こす
会計後の内容を直したい 会計確定後は金額が確定した記録として扱われる仕様 会計「前」の画面でのみ商品追加・削除が可能。確定後の訂正は現状未対応(要相談)
お客様の注文が反映されない LINEのIDトークン期限切れ、または通信エラー お客様に画面の再読み込みをお願いする
短時間に注文が集中していると出る 10分間に5件を超える注文でスパム対策が作動 正常な仕様。しばらく待って再度注文
画像がアップロードできない 非対応の形式、または4MB超過 JPEG/PNGで保存し直す(自動リサイズはされるが形式非対応は不可)
Emergency Response

サイトが落ちた・様子がおかしいとき

🚨

UptimeRobotから「Down」のメールが届いたら、まず落ち着いて下記の手順で切り分けてください。

ヘルスチェックを直接開く

/api/health にアクセスし、{"status":"ok"} が出るか確認。出なければDB(データベース)側の障害の可能性。

Vercelの稼働状況を確認

vercel.com のプロジェクトダッシュボードでデプロイが失敗していないか、または vercel-status.com で大規模障害が起きていないか確認。

Sentryでエラー内容を確認

studio-poplar.sentry.io の Issues 一覧に新しいエラーが出ていれば、そこにスタックトレースと発生状況が記録されている。

自力での解決が難しければ開発元に連絡

上記3つのスクリーンショットを添えて共有すると、原因の特定が早くなります。

データを誤って壊してしまった場合

このシステムのデータベース(Neon)は「Point-in-time Restore」という方式で、ファイルバックアップではなく 過去の任意の時点まで巻き戻す仕組みです。保持期間はプランにより24時間〜30日。気づいたらすぐ、 Neonのコンソールから復元操作を行うか、開発元に連絡してください。時間が経つほど復元できる範囲が狭くなります。
